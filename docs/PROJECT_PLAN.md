# 튜너쓸말 상세 기획 요약 (v1.0)

원본: 「튜너쓸말 · 상세 기획서 및 AI 프롬프트」 PDF. 이 문서는 개발에 필요한 부분만 요약하고, 엔진 검토 결과를 반영했습니다.

## 1. 한 줄 정의
브라우저가 인식하는 오디오 입력 장치(오인페 등)로 베이스 신호를 받아 4현 표준 튜닝의 음정·Hz·센트 편차를 실시간으로 보여주는 웹 튜너.

## 2. 확정 사항
| 구분 | 결정 |
|---|---|
| 이름 | 튜너쓸말 (튜너 쓸래 말래) |
| 대상 | 4현 표준 E1 · A1 · D2 · G2 |
| 환경 | macOS · Windows 데스크톱 주요 브라우저 우선 |
| 입력 | 특정 장비 전용이 아닌, 브라우저에서 선택 가능한 모든 audioinput |
| 범위 | 1차(MVP)는 튜너만. 박자 연습 탭 히키락스타는 튜너 배포 이후 같은 웹의 두 번째 탭으로 추가 (9장). 계정·서버는 계속 제외 |
| 엔진 | fgnass/tuner (MIT)의 음정 검출 코드 재사용. 앱/UI/흐름은 직접 구현 |
| 디자인 | 기능 검증 후 확정. 방향은 "하찮고 귀여운 캐릭터" |

## 3. 사용자 흐름
페이지 열기 → 권한 허용 → 입력 장치 선택 → 레벨 미터로 신호 확인 → 한 줄씩 연주 → 음정/센트 확인하며 조율 → 필요 시 장치·게인 변경

### 화면 상태
| 상태 | 동작 |
|---|---|
| 권한 전 | 권한 안내 + 시작 버튼 |
| 장치 선택 | 장치 목록. 권한 전에는 이름이 비어 있을 수 있음을 안내 |
| 연결됨/무신호 | 장치명 + 레벨. 무신호면 케이블/입력 확인 안내 |
| 분석 중 | 음정·Hz·센트, 안정도 낮으면 불확실 표시 |
| 오류 | 권한 거부·장치 분리·미지원을 구체적 문장으로 |

## 4. 기능 명세
F-01 입력 권한 · F-02 장치 열거 · F-03 장치 선택 · F-04 입력 레벨 · F-05 음정 검출 · F-06 음정 표시 · F-07 튜닝 목표 · F-08 오류/상태 (README 표 참고)

## 5. 기술 구조
입력 장치 → MediaStream → AudioContext → 하이패스/로우패스 → AnalyserNode(8192) → 음정 엔진(YIN+FFT) → 안정도 게이트 → 목표 음 비교 → UI

```
src/
  app.tsx
  components/   DeviceSelector, InputLevelMeter, TunerDisplay, TuningPreset, StatusMessage, Mascot
  audio/        deviceManager.ts, audioEngine.ts, inputLevel.ts
  lib/          pitch.ts, fft.ts, oneEuro.ts, notes.ts  ← fgnass/tuner에서 이식 (MIT)
  hooks/        useAudioInput.ts, usePitch.ts
  tests/
```

### 원본 엔진 대비 차이 (검토 결과)
- 원본 `usePitch.ts`는 `getUserMedia`에 `deviceId`를 지정하지 않아 **기본 입력만 사용** → F-02/F-03 직접 구현 필요.
- 원본에는 **입력 레벨 미터 없음** → F-04 직접 구현.
- 원본은 echoCancellation/noiseSuppression/autoGainControl을 false로 요청함 (기획과 일치). 실제 적용값은 `track.getSettings()`로 표시 추가.
- 원본 UI는 Preact. 엔진(`src/lib`)은 프레임워크 무관.

## 6. E1 검증 전략
목표 주파수: E1 41.20Hz · A1 55.00Hz · D2 73.42Hz · G2 98.00Hz

- A. 장치 인식: 2종 이상 장치에서 목록·선택·재연결
- B. 입력 레벨: 각 현 신호 유입 확인 (음정 검출과 별도)
- C. 기준 톤: 41.20Hz 부근 테스트 톤으로 오차 측정
- D. 실제 악기: 각 현 반복 연주, 성공률·안정성·옥타브 오검출 기록
- E. 환경 비교: 게인·샘플레이트·브라우저·OS 변경
- F. 실패 조건: 무신호, 소음, 복수 현, 저게인, 클리핑, 장치 분리

표시 규칙: 신뢰할 수 없는 결과는 표시하지 않고 '신호 없음 / 분석 중 / 신호 불안정'을 구분. 정확도 목표는 실험 후 수치화.

## 7. 개발 단계
0 준비 → 1 입력 장치 → 2 입력 레벨 → 3 엔진 평가(E1) → 4 음정 분석 → 5 튜너 UI → 6 검증 → 7 디자인/배포 → 8 히키락스타 수요 테스트 → 9 히키락스타 v0 → 10 히키락스타 v1 → 11 히키락스타 v2

## 9. 히키락스타: 방구석 베이스 박자 연습 (튜너 이후)

박치 탈출용 연습 도구 **히키락스타**. 튜너와 **같은 웹의 두 번째 탭**으로 넣고, 오인페 장치 선택·입력 레벨·캐릭터 표정 시스템을 그대로 재사용한다. 근거와 레퍼런스: [박자 연습 기능 아이디어 검토](https://claude.ai/artifact/QLXBLKL1huX84fpLRp7wLn).

### 핵심 흐름
내 음원 파일 업로드 → 브라우저 안에서 BPM·첫 박·비트 위치 분석 → 사용자가 보정 → 곡 + 맞춘 메트로놈 동시 재생 → 리듬 UI로 박자 보기 → (v1) 오인페로 들어온 내 연주를 박자와 비교해 판정

### 기능 명세
| ID | 기능 | 설명 |
|---|---|---|
| B-01 | 음원 업로드 | mp3·wav·m4a 드래그 앤 드롭. `decodeAudioData`로 디코딩. **서버로 보내지 않음** |
| B-02 | 템포·비트 분석 | BPM, 첫 박(offset), 비트 위치 추정. 박자표는 4/4 기본, 3/4 등은 사용자가 선택 |
| B-03 | 비트 수동 보정 | 탭 템포(스페이스바 두드리기), "여기가 1박" 클릭, BPM ±, 반/두 배 템포 전환. 자동 분석이 틀려도 연습할 수 있게 하는 필수 화면 |
| B-04 | 맞춤 메트로놈 | 곡과 클릭을 함께 재생. `AudioContext` 시계로 미리 예약 (setTimeout 금지). 1박 강조음, 클릭/곡 볼륨 분리 |
| B-05 | 리듬 UI | 노트가 판정선으로 흘러오는 타이밍 화면. 1박은 큰 노트, 나머지는 작은 노트 |
| B-06 | 지연(싱크) 보정 | 출력·입력 지연을 측정해 저장하는 보정 화면. 판정 전에 반드시 거침 |
| B-07 | 연주 판정 | 오인페 입력의 온셋(소리 시작)을 검출해 가장 가까운 비트와의 시간 차(ms) 계산. "딱! / 쪼끔 빨라 / 쪼끔 늦어 / 어디 갔어?" + 평균 ms 숫자 표시 |
| B-08 | 연습 보조 | 느리게 재생(피치 유지), 구간 반복 |

### 리듬 UI 원칙 (장르 문법만 빌리기)
- 흐르는 노트·판정선·판정 등급·콤보 같은 **장르 공통 형식만** 쓴다.
- 특정 게임의 캐릭터, 노트 색 구성, 판정 문구, 효과음, 로고·폰트, 화면 배치는 가져오지 않고, 게임 이름을 마케팅에 쓰지 않는다.
- 노트는 줄감개 모양 "쓸말이" 발자국. 빠르면 앞으로 고꾸라지고, 늦으면 졸고, 맞으면 만세 (튜너 표정 재사용).
- 숫자는 가리지 않는다: 판정 결과는 평균 몇 ms 빨랐는지/늦었는지로도 보여준다.

### 제외 (하지 않는 것)
- **유튜브 링크 → mp4/mp3 변환**: YouTube 약관(다운로드·자동화 접근 금지)과 저작권 문제로 제외. 변환 서비스 운영자가 가장 큰 위험을 진다.
- 음원을 서버에 올리거나 저장·공유하는 기능.
- 대안으로 검토 가능: 유튜브 공식 임베드 + 탭 템포(오디오 추출 없음, API 약관 별도 확인), 라이선스가 명확한(CC0 등) 연습용 트랙 내장.

### 기술 후보
| 할 일 | 후보 | 메모 |
|---|---|---|
| BPM + 첫 박 | web-audio-beat-detector `guess()` | 가볍다. 어쿠스틱·라이브 곡엔 약함. 라이선스 채택 전 확인 |
| 비트 위치·신뢰도 | Essentia.js `RhythmExtractor2013` | 정확하지만 **AGPL 계열로 알려져 있어 채택 전 라이선스 확인 필수** |
| 메트로놈 | Web Audio `OscillatorNode`/짧은 샘플 예약 | 오디오 시계 기준 |
| 온셋 검출 | 튜너 입력 파이프라인 + 에너지/스펙트럼 플럭스 | 튜너 1·2단계 코드 재사용 |
